| 1 | `rm --force` can kill unrelated processes | `src/commands/rm.rs` | 35–50 | `rm` uses a raw (unreconciled) meta load, so after an abnormal stop (e.g. pi-vm was SIGKILLed and the pdeathsig killed CH without the state update at `vm.rs` 608–611 running), `raw.state` is still `Running` with a dead `ch_pid`. `rm --force` then sends SIGTERM to that recorded pid (39) with no liveness/ownership check — if the pid was reused by an unrelated process, that process is killed. The `pgrep -f <disk path>` sweep (42–48) compounds this: the pattern is an ERE (dots in the path match any char) and matches *any* process whose command line contains the path string (editors, backup tools, `tail -f`), and every match is SIGTERM'd. PLAN.md §9b deferred the stale-pid risk, but the raw-load + pgrep combination makes it reachable from a destructive command. |

| 2 | Toolchain: width specifiers don't pad custom Display types | Entire project | — | rustc 1.98.1 (this build) silently ignores `{:N}`/`{:>N}` width specifiers for types with a custom Display/Debug impl (verified: `format!("{:8}", enum_with_display)` → 7 chars; same on a struct; `{:8?}` on a derived Debug enum also unpadded), while string types (`&str`, `String`, `Cow`, `Box<str>`) pad normally. Variable widths (`{:width}`/`{:name}`) and fill chars (`{*^8}`) are rejected as "unknown format trait". This is what caused the `pi-vm list` misalignment (STATE value unpadded → every column after it one char left of the header); `list.rs` now works around it with explicit `pad()` + `state.to_string()`. Any future table formatting in this repo must do the same. |
